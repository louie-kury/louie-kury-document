# 작업 시작·계획 검토·자동 진행 규칙 수정 계획

- 작성일: 2026-11-20
- 상태: 실행 중. 사용자가 순서를 구체화한 뒤 “이렇게 돌아가도록 수정하고, pr 올리고 대기”라고 명시해 이번 지침 수정·검증·PR 게시를 허용했다. 같은 실행 권한을 다시 확인하지 않는다.
- 실행 이슈: [#14](https://github.com/louie-kury/louie-kury-document/issues/14), 작업 브랜치: `chore/14-plan-issue-workflow`.
- 현재 범위: 공통 문서 레포의 지침·역할 설정·템플릿 수정과 검증·리뷰·커밋·푸시·PR 게시. 다른 서비스 레포의 실제 파일은 변경하지 않는다.

## 바꾸려는 동작

사용자가 “이런 기능 만들어줘”라고 요청하면 다음 순서로 진행한다.

1. 실제 저장소 상태를 확인하고 해당 작업의 PRD·ERD·API·정책·컨벤션 등 관련 문서를 모두 찾아 읽는다. 무관한 문서 전체를 순회하지 않는다.
2. planner가 문서 근거에 따라 사람이 읽을 수 있는 계획서를 작성한다.
3. 사람이 계획서를 검토하고 승인한다. 승인 전 이슈 등록·브랜치 생성·구현을 진행하지 않는다.
4. 승인한 계획을 기준으로 이슈를 만들고 사람의 승인을 받는다.
5. 이슈 승인 후 브랜치를 생성하고 승인 범위의 구현·검증·필요한 리뷰·문서 정리까지 이어서 수행한다.

일반 기능 개발에는 계획 승인과 이슈 승인이라는 두 게이트를 적용한다. 단계나 담당자가 바뀌었다는 이유만으로 추가 승인을 요구하지 않는다. 설계·리뷰·문서만 요청한 작업은 요청 범위를 유지한다. 이번 작업은 계획 제시 후 사용자가 수정·PR 게시까지 명시적으로 지시한 범위를 이어서 실행하며, 이를 일반 기능 요청의 승인 생략 규칙으로 확대하지 않는다.

## 제안하는 수정

1. **시작 순서를 명시한다.** 관련 문서 모두 확인 → planner 계획서 → 계획 승인 → 이슈 생성 → 이슈 승인 → 브랜치 생성 → 구현·검증 순서로 통일한다. 제품 기능은 PRD에서 기능을 찾고 ERD의 관련 엔티티·관계·필수값·제약, API 공통 계약과 해당 도메인, 관련 정책·컨벤션까지 확인한다. 작업과 무관한 자료는 대상에서 제외하되 읽기 비용 절감을 이유로 관련 자료를 생략하지 않는다. 자료에 답이 있으면 다시 묻지 않고, 없거나 서로 충돌할 때만 근거와 함께 질문한다.
2. **계획서를 필수 산출물로 정한다.** 이슈 유무와 관계없이 기능 구현·수정 전에 작성한다. 기존 유효한 설계는 연결하고 이번 변경·실행 순서·검증 계획을 추가한다. 작은 변경은 한 페이지 안에서도 작성할 수 있다. 대상 서비스 작업은 해당 레포의 `docs/plans/`, 공통 하네스 작업은 공통 문서 레포의 `docs/ai/plans/`를 기본 위치로 제안한다.
3. **일반 개발과 학습 모드를 구분한다.** 일반 작업에서 AI는 문서 근거를 읽고 권장안을 계획서로 제시할 수 있다. 사용자의 선택·이유·승인은 만들어내지 않는다. 일반 planner 진입에서 VibeWise 자동 적용을 제거하고, Codex 어댑터에 명시적 학습 모드에서만 사용하는 기준을 둔다. 사용자가 학습 모드를 요청했을 때는 기존 접근법 질문과 학습 체크포인트를 유지한다. 스킬 본문·동작 가이드의 광범위한 변경은 하지 않고, 자동 적용 경로가 남아 있을 때만 해당 연결을 정리한다.
4. **승인 후 이어서 수행할 책임을 메인에 둔다.** 계획 승인은 이슈 작성을 허용하고 이슈 승인은 브랜치 생성과 승인 범위의 구현·검증을 허용한다. 담당자 반환은 메인에게 돌아오는 단계 종료이며 사용자 승인 대기가 아니다. 메인은 결과를 확인하고 다음 역할을 배정한다. 두 게이트를 통과한 뒤 계획 안의 구현·관련 검증·리뷰·문서 동기화·허용된 재작업에는 반복 승인을 요구하지 않는다. 커밋·푸시·PR은 사용자가 요청했고 계획에 포함된 경우에만 이어서 수행한다.
5. **멈출 조건을 분명히 한다.** 계획 승인 대기와 이슈 승인 대기, 중요한 요구사항·설계·범위 변경, 문서로 해결되지 않는 필수 정책, 권한이나 실행 환경 문제, 재작업 한도 도달, 사용자의 중단 요청에서 해당 작업을 멈춘다. 독립적으로 가능한 작업은 계속하되 승인 전 후속 게이트 작업을 먼저 수행하지 않는다. 진행 상황 보고와 역할 전환은 중단 사유가 아니다. PR 게시까지 허용된 작업은 게시 후 사람이 검토한다. 최종 머지는 사람이 한다.
6. **서비스 시작 경로에도 전달한다.** 새 서비스 AGENTS 템플릿에 메인의 역할 조정과 시작·계획·승인 후 진행 규칙을 연결한다. 이번 PR은 공통 문서 레포에 한정하며 기존 `louie-kury-pet-service/AGENTS.md` 등 서비스의 실제 파일은 수정하지 않는다. 기존 서비스에는 템플릿 내용과 공통 경로를 해당 레포 작업에서 별도로 전파해야 한다.

## 계획서에 담을 내용

- 목적과 사용자가 기대하는 결과, 이번 범위와 제외 범위
- 대상 저장소·브랜치·기존 변경, 참고한 PRD 기능·ERD 엔티티·API 계약의 경로와 절
- 현재 동작과 제안 동작, 중요한 선택의 대안·이유·미정 사항
- 변경할 파일과 역할, 계획 승인 → 이슈 생성·승인 → 브랜치 → 구현·검증·리뷰·문서 정리 순서
- 정상·경계·실패·기존 동작 보존 기준과 실행할 검증, 환경 때문에 실행할 수 없는 범위
- 사용자 검토 상태와 승인 범위, 승인 후 이어서 수행할 일과 멈출 조건

사용자가 말한 이유와 AI 제안의 이유를 구분한다. 내부 계획 도구의 목록만 제시하고 사람이 읽을 계획서를 생략하지 않는다.

## 두 승인 이후 실행과 검증

일반 흐름에서는 계획 승인 후 이슈를 작성하고 이슈 승인 전에는 브랜치·구현을 시작하지 않는다. 이번 작업은 사용자가 제시된 계획에 수정·PR 게시까지 명시적으로 지시한 실행 범위에 따라 이슈 #14와 작업 브랜치를 만들고 진행한다.

1. 이슈 승인 후 대상 저장소의 브랜치·기존 변경을 다시 확인하고 Git 컨벤션에 맞는 작업 브랜치를 생성한다. 기존 브랜치의 변경은 보존한다. 위 지침·템플릿·역할·스킬의 충돌 문구를 수정하고 관련 링크를 확인한다.
2. `python3 -B scripts/ai/harness.py check-config`로 JSON/TOML·역할 정의·하네스 진입점과 링크 검사를 실행한다.
3. 테스트 담당자가 변경에 맞는 회귀 검증을 수행한다. 단순 특정 문장 포함 검사로 동작을 보장한다고 주장하지 않고, 끊어진 계획서 연결·잘못된 설정·누락된 파일을 잡는 구조 검사를 우선한다. 설정이나 검사 실행 코드가 바뀌면 `python3 -B scripts/ai/harness.py verify`도 실행한다.
4. 독립 reviewer가 다음 상황을 지침과 대조한다: 일반 기능 요청에서 관련 문서 확인 후 계획 작성, 계획 승인 전 이슈 생성 차단, 계획 승인 후 이슈 생성과 이슈 승인 대기, 이슈 승인 전 브랜치·구현 차단, 두 승인 후 브랜치 생성과 연속 진행, 이미 유효한 설계가 있는 수정, ERD와 API의 충돌, 승인 후 역할 전환, 승인 범위 내 재작업, 재작업 한도 초과, 리뷰만 요청한 작업, 사용자가 명시적으로 요청한 학습 모드.
5. 실제 새 채팅에서 기능 요청을 해 관련 문서 확인·계획서 작성·계획 승인 대기·이슈 생성·이슈 승인 대기·브랜치 생성·구현과 검증의 연속 진행을 관찰할 수 있으면 별도 행동 검증으로 기록한다. 이 관찰이 없으면 정적 검사와 문서 리뷰 결과까지만 완료로 보고한다.

수정 전 기준 커밋 `667ecbb`에서 메인이 실행한 `python3 -B scripts/ai/harness.py check-config`는 종료 코드 0과 `PASS A`를 반환했다. 수정 후 검증과 리뷰는 별도 결과로 보고한다. 문구와 설정 검사가 통과하더라도 모든 후속 채팅에서의 준수를 보장하지 않으며, 제품 서버·DB·외부 API 검증을 의미하지 않는다.

## 이번에 승인된 실행 범위

사용자의 최신 명시적 지시에 따라 이번 공통 하네스 변경·검증·리뷰·문서 정리와 커밋·푸시·PR 게시까지 진행하고 PR 게시 후 대기한다. 최종 머지는 포함하지 않는다. 계획의 변경 범위나 중요한 판단이 달라지는 경우에만 해당 부분을 다시 검토받는다. 기존 서비스 AGENTS와 실제 새 채팅에서의 행동 검증은 이번 공통 문서 PR에 포함되지 않는 한계로 보고한다.
