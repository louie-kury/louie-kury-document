# 서비스 레포 작업 규칙

- 한국어로 응답하고 시작할 때 경로·브랜치·미커밋 변경과 요청 범위를 확인한다.
- 공통 문서는 `../louie-kury-document/docs/`에 있다. 공통 문서의 `ai/ROUTING.md`에 있는 읽기 규칙에 따라 필요한 자료를 확인한다.
- 기능 개발은 조사 → 계획 승인 → 이슈 작성·승인 → 브랜치 → 구현·검증 순서로 진행한다. 상세 기준은 공통 문서의 `ai/HUMAN_GATES.md`를 따른다.
- 역할·검증·수정 확인·인계는 공통 문서의 `ai/WORKFLOW.md`, 이슈·브랜치·커밋·PR은 `convension/GIT_CONVENTIONS.md`를 따른다. 커밋·push·PR은 요청 범위에서 진행하며 최종 승인과 머지는 사람이 한다.
- 스택과 빌드·테스트 명령은 이 서비스의 README와 빌드 설정에서 확인한다. 실제 결과와 미검증 범위를 보고한다.
- 사용자 변경·전역 설정을 보존하고 비밀값·대화 전문·고객 정보를 저장하지 않는다.
