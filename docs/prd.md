## 1. 문서 목적과 읽는 방법

본 문서는 각 기능을 개발할 때 에이전트와 사람이 함께 읽는 **제품 정책·요구사항의 기준 문서**다. 서비스 전체 범위와 기능별 기대 동작, 공통 정책, 미정 질문, QA의 연결을 관리한다. 특정 기술 스택, DB 구조, 서비스 분리 방식은 확정하지 않는다.

### 1.1 기준과 우선순위

- **[확정]**은 기존 유효한 합의와 최신 요구사항정의서·사용자 지시를 반영한 제품 요구사항이다. 충돌 시 최신 사용자 지시를 우선한다. SQL에 컬럼이 없다는 이유로 제품 요구를 삭제하지 않으며 차이는 11장과 D18에서 관리한다.
- **[미정]**: 제공된 PRD에서 미확정인 항목이다. 해당 정책에 의존하는 작업에 착수하기 전에 사용자 또는 사람이 지정한 제품·운영 담당자에게 질문하고, 답변을 문서에 반영한 뒤 구현한다. 담당 분야 이름은 결정권자 지정이 아니다.
- 6장의 기능별 요구사항은 7장 상담 상태, 8장 정보 접근, 10장 공통 품질 정책과 함께 적용한다. 화면 목록(9장), 정보 관계(11장), QA(14장)는 이를 추적하며 독립적으로 운영 정책을 추가하지 않는다.
- 최신으로 문서에 반영된 사람의 결정이 변경 이력과 연결되어 기준이 된다. 코드·테스트·화면 시안·에이전트의 추측으로 기존 요구사항을 덮어쓰지 않는다. 절 사이에 충돌이 남으면 해당 부분을 미해결로 기록하고 사람에게 확인하며, 임의로 우선순위를 골라 구현하지 않는다.
- 초기 출시 범위는 4장 전체다. 미정 항목이 있다는 이유로 기능을 임의 삭제하거나 MVP로 축소하지 않는다.

### 1.2 미정 처리와 개발 요청의 단위

미정 항목에는 권장 기본값이 없다. 입력 단위·허용 범위, 취소 기한, 권한 세부 범위, 내부 상태명(enum), DB·기술 스택을 개발자가 임의 확정하지 않는다. 특정 사례나 데이터 항목의 등장만으로 허용 범위·상태·보관 기간을 확정하지 않는다.

개발 요청에는 **기능 ID → 적용 공통 정책(절 번호) → 관련 D ID → 수용 기준·Q ID**를 함께 적는다. 6.10의 연결표와 12장의 질문 목록을 확인하고, 구현할 확정 범위와 답변을 기다릴 범위를 구분한다. 미정 정책에 의존하는 부분만 보류하고 독립적인 확정 작업은 진행할 수 있다. 사람의 답변이 오면 해당 D 항목과 관련 기능·상태·권한·QA를 함께 갱신한다.

수용 기준과 QA는 기대 동작이며 구현·검증 완료를 뜻하지 않는다. 미정 정책에 의존하는 기대값은 답변 후 구체화한다. 데이터 정합성과 타인 정보 접근 차단 등 기존 공통 품질 기준은 유지한다. 본 문서는 법률 검토, 상담 수단 연동 가능성 확인 또는 구현 검증의 결과물이 아니다.

## 2. 제품 목표

### 2.1 해결할 문제

1. 보호자가 반려동물의 건강 변화를 기억에 의존하여 관리하고 설명한다.
2. 상담이 필요해도 수의사를 찾고 건강 정보를 전달하는 과정이 분리되어 있다.
3. 상담 후 내용을 다시 확인하기 어려워 건강 관리의 연속성이 떨어진다.

### 2.2 제품 가치

**반려동물별 건강 관리 → 위치 기반 실시간 매칭 신청 → 가까운 병원부터 상담 가능한 수의사 탐색 → 채팅·화상 상담 → 상담 이력·일지 확인**을 하나의 흐름으로 제공한다. 반려동물 관리에서 기본 정보와 예방접종·병원 진료 이력을 함께 관리한다. 커뮤니티와 알림은 보호자의 정보 교류를 지원한다.

### 2.3 성과 측정 [미정]

측정할 지표, 산식, 수치 목표, 집계 기간은 미정이다. 성과 측정 기능 개발 전 담당자에게 어떤 지표가 필요한지 질문한다.

## 3. 사용자와 핵심 시나리오

|---|---|---|
| 보호자 | 반려동물별 건강·접종·진료 이력과 실시간 상담 | 고양이의 구토 기록을 남기고 위치 기반 매칭으로 상담받은 뒤 일지 조회 |

상담 상대 정보·가용 상태·수락 결과·일지의 제공 인터페이스는 D07·D17에서 확정한다.

## 4. 출시 범위

### 4.1 초기 출시 필수 범위 [확정]

- 보호자 일반 가입·로그인, 카카오·네이버 소셜 가입·로그인, 계정 복구·마이페이지·탈퇴
- 여러 반려동물 등록·조회·수정·소프트 삭제, 강아지·고양이 지원
- 반려동물 관리 안에서 예방접종과 병원 진료 이력 등록·조회·수정·소프트 삭제
- 건강 기록 입력·수정·소프트 삭제, 달력·타임라인·상세와 미디어
- 위치 기반 실시간 매칭 신청·대기·취소·결과, 채팅·화상 상담과 종료·이력·일지 조회
- 완료 상담 평가·후기
- 커뮤니티 게시글·댓글·대댓글·좋아요·신고, 사용자 팔로우·언팔로우·팔로워/팔로잉 목록·수·상태 조회, 댓글·대댓글·팔로우 이벤트 알림
- 공통 미디어 업로드·검증·연결·조회·교체·제거·정리, 본인 알림 조회·읽음·미읽음 수·실시간 갱신

우선 개발 대상은 요구사항정의서의 파란색 표시 기능인 가입·로그인·계정 복구, 팔로우·팔로잉, 반려동물 등록 관리, 예방접종 등록 관리, 알림, 공통 미디어, 커뮤니티다. 상담 알림은 해당 정의서에서 미정으로 표시되어 별도 확정 후 다룬다.

### 4.2 초기 범위에 포함하지 않는 항목

- [확정] 지정 수의사 선택·희망 일시를 입력하는 예약 상담은 제공하지 않는다. 상담은 위치 기반 실시간 매칭만 제공한다.
- [확정] 상담 수단은 채팅·화상이다. 기존 안심번호 전화 요구는 최신 요구사항으로 대체한다.
- [확정] 쇼핑(shop)은 요구사항정의서에 v2로 표시되어 초기 범위에서 제외한다. 강아지·고양이 외 동물은 향후 확장한다.
- [미정] 지도 메뉴의 지역·현재 위치·진료 분야 필터는 요구사항에 있으나 상세 조회 동작·데이터 제공 범위는 D16에서 정한다. 지도에서 지정 예약을 시작하는 흐름을 추가하지 않는다.
- [미정] 건강 그래프·통계는 도입 결정 전까지 필수 범위에서 제외한다.

범위 밖 기능은 별도 변경 요청으로 영향과 완료 기준을 정의한다.

## 5. 주요 사용자 흐름

### 5.1 보호자

일반 또는 소셜 가입·로그인 → 반려동물 등록 → 건강·접종·진료 기록 관리 → 상담받기 → 본인 반려동물·채팅/화상 선택 → 증상·이미지 입력 → 위치 확인 → 실시간 매칭 신청 → 매칭 상태·대기 시간 확인 또는 취소 → 매칭된 수의사 이름·병원 확인 → 상담 연결·진행·종료 → 상담 시간·상대 확인 → 내역·일지·첨부 조회 → 평가·후기 작성

상담 내역에서 일지가 아직 제공되지 않았으면 “아직 수의사가 상담일지를 작성하지 않았어요” 등의 안내를 표시한다. 종료 화면과 일지 작성 완료를 같은 사건으로 가정하지 않는다.

### 5.2 상담 연동 경계

상담 상대의 가용 정보·수락 결과를 받아 매칭하고, 상담 종료 결과와 제공된 일지를 보호자에게 보여준다. 제공 주체·연동 인증·수락 및 종료 이벤트·일지 갱신 계약은 미정이다.

## 6. 기능 요구사항과 수용 기준

각 항목의 [확정]은 현재 범위에 반영한 요구사항이며, 수용 기준은 그 기대 동작이다. [미정] 문장과 질문은 구현 지시가 아니다. 실제 구현·검증 완료를 의미하지 않는다. 모든 기능에는 10장의 공통 품질 요구사항이 적용되며, 기능별 연결은 6.10을 따른다.

### 6.1 보호자 계정 — ACC

**ACC-01 가입·로그인·복구·마이페이지**

- [확정] 일반 로그인은 아이디·비밀번호를 사용한다. 일반 가입은 이름, 전화번호, 성별, 생년월일, 주소, 닉네임, 아이디, 비밀번호, 이메일을 입력한다. 한 이메일당 한 계정이며 닉네임은 최대 30자, 비밀번호는 영문·숫자·특수문자를 포함한 8~20자다.
- [확정] 소셜 제공자는 카카오·네이버다. 제공자 식별값을 저장하고 별도 비밀번호는 NULL로 관리한다. 제공자·식별값으로 소셜 계정을 구분한다.
- [확정] 소셜 닉네임 제공에 동의하면 제공값을 사용하고, 제공받지 않으면 랜덤 생성 후 직접 수정할 수 있다. 이름·전화번호는 필수이며 제공받지 못하면 직접 입력한다.
- [확정] 일반·소셜 가입 모두 사용자가 입력한 이메일로 인증번호를 발송하고 인증을 완료한 뒤 가입한다. 이미 가입된 이메일이면 신규 가입을 제한하고 기존 계정 로그인을 안내한다.
- [확정] 일반 회원 프로필은 MongoDB에 저장한다.
- [확정] 아이디 찾기는 가입 이메일로 인증번호를 발송하고 인증 후 아이디를 안내한다. 마이페이지는 닉네임·이메일·전화번호·반려동물 수를 보여주고 닉네임·이메일·전화번호·일반 계정 비밀번호를 수정한다.
- [미정] 비밀번호 찾기의 시트 문구는 이름·아이디 일치 후 변경 화면 진입이다. 이름·아이디 조회와 실제 변경 권한을 구분하고, 변경 전 본인확인 수단·토큰·유효시간은 D11에서 확정한다. 소셜 계정에 일반 비밀번호를 새로 부여할지 자동으로 결정하지 않는다.
- **수용 기준:** 이메일 중복 가입을 차단하고 일반·소셜 가입 모두 입력 이메일의 인증번호 인증 전에는 가입을 완료할 수 없다. 일반 회원 프로필은 MongoDB에 저장한다. 미인증 복구 요청은 비밀번호 변경을 완료할 수 없다. 로그인한 사용자는 본인 계정·반려동물·상담만 접근한다.

**ACC-03 탈퇴·계정 상태와 진행 중 상담**

- [확정] 보호자는 회원 탈퇴를 요청할 수 있으며 소프트 삭제한다. 계정 상태에 따른 본인 정보 접근을 서버에서 검사한다.
- [미정] 탈퇴 본인확인, 진행 중 매칭·상담 처리와 보관 기간은 D11에서 정한다.
- **수용 기준:** 탈퇴 요청과 진행 중 상담 처리가 경합해도 상담 이력이 유실되지 않고, 확정된 정책에 따라 상태·접근 권한을 함께 처리한다.

### 6.2 반려동물 관리 — PET

**PET-01 반려동물 등록·조회·수정·삭제**

- [확정] 한 보호자가 여러 반려동물을 등록하고 각각의 정보를 관리한다. 초기 지원 동물은 강아지·고양이다.
- [확정] 목록은 이름, 종·품종, 프로필 이미지, 나이, 성별을 표시한다.
- [확정] 상세는 이름, 종·품종, 프로필 이미지, 생년월일·나이, 성별, 중성화 여부, 체중, 기본 예방접종 여부를 표시한다.
- [확정] 등록·수정 항목은 이름, 종·품종, 프로필 이미지, 생년월일, 성별, 중성화 여부, 체중, 기본 예방접종 여부다. 프로필 이미지는 MED-01 공통 미디어를 사용한다.
- [확정] 보호자는 본인 반려동물을 소프트 삭제한다. 삭제한 반려동물은 목록·상세에서 제외하고 직접 ID로 조회·수정할 수 없다.
- **수용 기준:** 등록한 정보가 해당 반려동물의 목록·상세에 반영되고 수정 결과가 일치한다. 여러 동물의 정보가 섞이지 않으며 타인의 동물 조회·수정·삭제를 거부한다. 삭제 후 재조회와 기존 프로필 이미지 접근에도 현재 권한을 적용한다.
- [미정] 항목별 필수 여부, 생년월일을 모르는 경우, 나이 산식, 체중 단위·범위·이력 연계, 기본 접종 여부 입력·산정 기준은 D12에서 확정한다. 삭제 시 연결된 기록의 보관과 진행 중 상담 처리는 D11에서 정한다.

**PET-02 예방접종 등록·조회·수정·삭제**

- [확정] 반려동물 관리에서 예방접종을 관리할 본인 반려동물을 선택한다. 접종 이력은 선택한 동물에 연결한다.
- [확정] 목록에는 예방접종명, 접종일, 다음 접종 예정일을 표시한다.
- [확정] 상세에는 예방접종명, 접종일, 다음 접종 예정일, 접종 차수, 접종 병원명, 메모를 표시한다. 메모에는 접종 후 특이사항 등을 기록한다.
- [확정] 등록·수정은 상세와 같은 항목을 입력받고, 보호자는 본인 동물의 접종 이력만 변경할 수 있다.
- [확정] 접종 이력은 소프트 삭제하며 삭제한 항목은 목록·상세에서 제외한다. 직접 ID로 접근해 조회·수정하는 것도 차단한다.
- **수용 기준:** 동물을 바꾸면 해당 동물의 접종 목록만 표시된다. 등록·수정값이 목록·상세에 일치하고 타인의 동물·접종 이력 접근을 거부한다. 삭제 후 원본은 보관하되 조회에서 제외한다.
- [미정] 항목별 필수 여부, 접종명 선택·입력 방식, 접종 차수·날짜 허용 범위와 다음 예정일 미정 시 입력 방식은 D12에서 확정한다.

**PET-03 병원 진료 관리**

- [확정] 반려동물 관리 안에서 진료 이력을 등록·조회·수정·소프트 삭제한다. 목록은 진료일·동물병원명·진료 항목을 표시한다.
- [확정] 상세·등록·수정 항목은 진료일, 동물병원명, 진료 항목, 진료 사유, 진단명, 진료 내용, 복약 안내, 진료비, 다음 방문 예정일, 메모다.
- **수용 기준:** 본인 동물에 연결된 진료만 관리하고 삭제 상태를 조회에 반영한다. 금액 단위·범위, 필수값과 날짜 관계는 D12에서 확정한다.

기능과 화면을 반려동물 관리에 통합한다. SQL의 반려동물·예방접종·병원진료는 별도 테이블이며 물리 테이블 통합을 요구하지 않는다. 첨부 SQL의 누락 필드는 11장·D18에서 추적한다.

### 6.3 건강 기록 — HLT

**HLT-01 기록 입력·관리**

- [확정] 날짜·시간별 변 상태, 상처, 복용약(복용 시간 포함), 식사·음수, 구토, 활동 변화, 체중, 기타를 등록·조회·수정한다. 상세 내용과 사진 등 미디어를 연결한다.
- [확정] 보호자는 본인 반려동물의 건강 기록을 소프트 삭제할 수 있다. 삭제 시각을 기록하고 상세와 첨부 원본을 보관한다.

[미정 — 기록 입력 기능 개발 전 질문]

- 각 유형의 필수값, 입력 단위, 소수점 정밀도, 허용 범위는 무엇인가?
- 구토·배변·상처의 상세 항목은 무엇이며, 발생하지 않은 상태도 기록하는가?
- 관찰 일시와 작성 일시를 어떻게 구분하고, 하루 여러 건을 허용하는가?
- 수정 허용 범위는 어디까지인가? 프로필 체중과 체중 이력은 어떻게 연결하는가?

**수용 기준:** 확정한 유형별 필수값·단위·범위에 따라 입력을 검증하고, 반려동물별로 기록을 분리한다. 구체적인 경계값 검증은 답변 후 정의한다.

**HLT-02 달력·목록 조회**

- [확정] 달력에서 기록이 있는 날에 점을 표시하고 날짜 선택으로 기록을 조회한다. 타임라인 목록에는 시간·카테고리·내용을 표시하고 상세로 이동한다.
- **수용 기준:** 같은 반려동물·날짜의 기록이 양쪽 화면에서 일치한다. 삭제된 기록은 달력·목록·상세에서 제외하며, 남은 기록이 없는 날짜는 빈 상태로 표시한다.

**HLT-03 예방접종·병원 진료 이력 — PET로 통합**

기존 HLT-03의 기능은 PET-02·PET-03으로 이관한다. 건강 기록 관리와 별개의 화면에서 중복 관리하지 않고 반려동물 관리에서 제공한다.

**HLT-04 건강 기록 미디어**

- [확정] 건강 기록의 사진 등은 MED-01 공통 미디어로 업로드·연결한다. 삭제된 기록과 첨부는 기존 URL로도 조회할 수 없다.
- **수용 기준:** 업로드 실패·제한 위반을 안내하고 재시도할 수 있다. 파일 요청마다 현재 권한과 원본 기록의 삭제 상태를 확인한다. 사용처별 제한은 D12·D19에서 확정한다.

### 6.4 상담 상대 정보 — VET

**VET-01 매칭된 수의사 정보**

- [확정] 매칭 완료 시 수의사 이름·소속 병원을 보여주고 상담으로 연결한다. 진행·종료·내역에서도 상대 수의사를 식별할 수 있다.
- [기존 합의] 공개 프로필의 사진·소개·평점·후기는 관련 데이터가 제공되는 범위에서 유지하며 필드·조회 경계는 D16에서 재확인한다. 보호자의 수의사 직접 선택·지정 예약 기능은 제공하지 않는다.
- **수용 기준:** 표시된 수의사와 실제 상담 상대가 일치하고 상대 정보 로딩 실패를 안내한다. 데이터 제공 주체·프로필 조회 계약은 D16·D17에서 확정한다.

### 6.5 상담 신청·매칭·연결 — CON

**CON-01 위치 기반 상담 신청**

- [확정] 보호자는 본인 반려동물 한 마리, 상담 방식(채팅·화상), 증상과 첨부 이미지를 선택·입력하여 신청한다. 위치를 기준으로 가까운 병원부터 상담 가능한 수의사를 탐색한다.
- **수용 기준:** 타인 동물·유효하지 않은 미디어를 제출할 수 없다. 중복 제출·재시도가 상담 요청을 중복 생성하지 않는다. 신청은 매칭 대기로 이어지며 수의사 선택·희망 일시 입력을 요구하지 않는다.

**CON-02 매칭 대기·수락 결과**

- [확정] 매칭 진행 상태·대기 시간·취소 버튼을 제공한다. 매칭되면 수의사 이름·소속 병원을 표시하고 선택한 수단으로 연결한다.
- [확정] 한 요청의 담당 수의사는 한 명만 확정한다. 취소·만료·수락이 경합해도 최종 상담 상태의 일관성을 유지한다.
- [미정] 수의사 가용 상태와 수락 결과의 제공 주체·인증·전달 방식은 D17에서 확정한다.
- **수용 기준:** 보호자가 진행 상태를 재조회할 수 있고 취소된 요청은 늦은 수락으로 연결되지 않는다. 동일 수락 통지는 중복 연결을 만들지 않는다.

**CON-03 채팅·화상 상담**

- [확정] 매칭 후 선택한 채팅 또는 화상으로 상담한다. 진행 화면은 수의사 정보·상담 시간·상담 화면·종료 버튼을 제공하고 종료 결과에 상담 시간·상담 수의사를 표시한다.
- [미정] 제공 업체, 실제 연결·종료 확인 기준, 상담 중 수단 변경, 재연결과 이력 보관은 D06에서 확정한다.
- **수용 기준:** 상담 당사자만 연결된다. 실패 시 “수의사와 연결하지 못했어요. 다시 연결해 주세요.” 등의 안내와 재연결을 제공한다. 연결 실패를 정상 상담 완료로 기록하지 않는다.

**CON-04 종료·취소·내역 조회**

- [확정] 보호자는 상담을 종료하고 내역을 조회한다. 목록은 상담 날짜·수의사 이름·반려동물 이름·상태, 상세는 상담 일시·수의사 정보·제공된 일지·첨부 파일을 표시한다.
- [확정] 보호자는 매칭 대기 중 요청을 취소할 수 있다. 매칭 후 취소의 허용 조건은 D04·D17에서 확정한다.
- [변경] 최신 요구사항은 일지 미작성 상태의 상담 상세 안내를 요구한다. 상담 종료·업무 완료의 구분과 일지 미작성 시 완료 기준은 D04·D07에서 확정한다.
- **수용 기준:** 본인 상담만 조회하고 상담 종료 후 일지 미작성 안내를 표시할 수 있다. 종료·완료·취소 재시도가 상담 상태를 중복 전환하거나 완료된 결과를 되돌리지 않는다.

**CON-05 위치 기반 실시간 매칭 정책**

- [확정] 상담은 카카오택시와 같은 위치 기반 실시간 매칭 방식만 제공한다. 가까운 병원부터 상담 가능한 상대를 탐색하고 보호자에게 매칭 상태·대기 시간을 실시간으로 표시한다.
- [기존 합의·최신 시트 미기재] 탐색은 요청 접수 0초 500m, 10초 1km, 20초 1.5km, 30초 5km, 40초 10km 순이며 전체 기한은 60초다. 마지막 단계는 남은 20초 동안 유지한다. 확대해도 전체 기한은 연장하지 않으며 매칭되면 탐색을 끝낸다. 최신 구현 연동에 이 세부값을 그대로 적용할지는 D17에서 재확인한다.
- [기존 합의] 대상 수의사에게 같은 요청을 중복 전달하지 않고 최초 수락자 한 명만 확정한다. 진행 중 상담이 있는 수의사의 중복 수락을 막는다. 상대의 가용 여부는 연동 계약으로 확인한다.
- [기존 합의] 미매칭이면 탐색을 종료하고 “지금 바로 상담할 수 있는 수의사를 찾지 못했어요.”를 안내한다. 안내창 닫기는 창만 닫고 재신청은 새 매칭이다.
- [기존 합의] 매칭 자체로 기존 건강 기록의 열람 권한을 부여하지 않는다. 신청에 포함한 증상·이미지의 전달 범위와 종료·취소 후 접근은 D05에서 정한다.
- [미정] 위치 확인·권한 거부 처리, 거리 산정, 대상 수 제한, 연동 수락 시간·실패 처리와 매칭 후 취소 조건은 D17에서 확정한다.
- **수용 기준:** 동시 수락·중복 이벤트·취소 경합에서도 한 명만 연결한다. 기한·반경 검증은 D17에서 재확인된 값으로 수행한다.

### 6.6 상담 일지·후기 — LOG / REV

**LOG-01 제공된 상담 일지 조회**

- [확정] 보호자는 본인 상담 상세에서 수의사가 작성해 제공한 일지와 첨부를 조회한다. 미작성·미제공 상태는 “아직 수의사가 상담일지를 작성하지 않았어요” 등의 안내로 표시한다.
- **수용 기준:** 일지가 없어도 상담 내역·종료 결과를 확인할 수 있다. 제공된 일지·첨부는 해당 상담 보호자만 조회하며 기존 건강 기록의 권한을 우회하지 않는다.
- [미정] 일지 데이터 제공 주체·갱신 계약, 공개 시점·보관 기간, 미작성과 연동 실패의 구분, 기존 완료 정책과의 연결은 D07에서 정한다.

**REV-01 평가·후기**

- [확정] 보호자는 완료된 상담에 대해 평가할 수 있고, 별점은 필수·텍스트는 선택이다. 평점과 후기를 프로필에 표시한다.
- **수용 기준:** 해당 상담 보호자만 완료 이후 작성할 수 있다. 별점 없이 저장할 수 없고 별점만으로는 저장할 수 있다. 동일 요청 재시도로 후기가 중복 생성되지 않는다. 평균 평점과 평가 수가 실제 공개 대상 평가와 일치한다.
- [미정] 상담당 허용 평가 수, 별점 범위, 후기 수정·삭제 가능 기간, 숨김 처리된 후기의 평균 평점 반영 정책(D16).

### 6.7 커뮤니티 — COM

**COM-01 게시글·댓글·반응**

- [확정] 첫 버전은 게시판 1개로 운영하고 향후 게시판 추가가 가능하도록 한다. 목록은 카테고리별로 필터링한다.
- [확정] 비회원도 공개 게시글의 목록·본문·첨부·좋아요 수·최상위 댓글을 볼 수 있다. 글쓰기나 답글 보기를 선택하면 로그인을 안내한다.
- [확정] 로그인한 사용자는 카테고리·제목·본문을 입력하고 사진·동영상을 첨부해 글을 작성한다. 작성자는 본인 글의 제목·본문·첨부를 수정하며, 파일은 MED-01의 저장·교체 규칙을 따른다.
- [확정] 작성자가 글을 삭제하면 목록·상세에서 숨기고 기존 사진·동영상 URL의 직접 접근도 차단한다.
- [확정] 로그인한 사용자는 댓글·대댓글을 작성한다. 최상위 댓글을 1단계로 하여 최대 4단계까지 허용한다.
- [확정] 작성자는 본인 댓글·대댓글을 수정할 수 있으나 하위 답글이 있으면 수정할 수 없다. 삭제 시 하위 답글이 있으면 “삭제된 댓글입니다”로 표시하고 답글을 유지하며, 없으면 해당 댓글을 숨긴다.
- [확정] 로그인한 사용자는 게시글·댓글·대댓글의 좋아요를 누르거나 취소할 수 있다. 같은 사용자의 중복 요청으로 좋아요 수가 늘어나지 않는다.
- [확정] 댓글·대댓글 작성에 따른 알림은 NTF-01에 연결하고 첨부 조회에는 원본 게시글의 현재 공개·삭제 상태를 적용한다.
- **수용 기준:** 비회원의 공개 열람과 로그인 필요 동작을 구분한다. 타인 콘텐츠 변경, 5단계 댓글 작성, 하위 답글이 있는 댓글 수정, 삭제·숨김 글의 새 댓글 작성을 거부한다. 댓글 삭제 표시·답글 보존과 좋아요 수가 실제 상태에 일치한다.
- [기존 합의] 연동으로 숨김 상태가 반영되면 작성자를 포함한 일반 사용자의 글·댓글·첨부 접근을 차단한다. 복구 시 이전 노출을 복원하되 별도 삭제·숨김 상태는 유지한다.

**COM-02 신고 접수**

- [확정] 로그인한 사용자는 게시글 메뉴에서 게시글 또는 작성자를 신고하고, 댓글 메뉴에서 댓글·대댓글을 신고한다.
- [확정] 신고를 해당 대상·관련 콘텐츠에 연결하고 신고자 정보는 대상자에게 공개하지 않는다.
- [미정] 신고 사유·필수 입력과 접수 후 상태·처리 결과 제공 경계는 D08에서 정한다.
- **수용 기준:** 비로그인 신고를 거부하고 신고 유형과 대상이 일치하는지 검사한다. 제출 실패를 성공으로 표시하지 않으며 타인에게 신고자 정보를 노출하지 않는다.

**COM-03 팔로우·팔로잉**

- [확정] 로그인한 사용자는 다른 사용자를 팔로우할 수 있다. 자기 자신을 팔로우하거나 동일 사용자를 중복 팔로우할 수 없다.
- [확정] 로그인한 사용자는 자신이 만든 팔로우 관계를 언제든 취소할 수 있다. 다른 사용자의 팔로우 관계는 취소할 수 없다.
- [확정] 사용자의 팔로워·팔로잉 목록과 각각의 수는 다른 사용자도 조회할 수 있다. 로그인한 사용자는 상대 프로필에서 본인이 현재 상대를 팔로우하는지 확인할 수 있다.
- [확정] 팔로우한 상대에게 NTF-01 알림을 생성하고 언팔로우 알림은 생성하지 않는다. 같은 팔로우 이벤트의 재시도는 관계와 알림을 중복 생성하지 않는다.
- [미정] 비회원의 목록·수 조회 허용 여부와 목록 정렬·페이지 조회 방식은 D08에서 정한다.
- **수용 기준:** 비로그인 팔로우·언팔로우, 자기 팔로우와 타인 관계 취소를 거부한다. 동시·중복 팔로우에도 관계는 한 건이며 프로필 상태·팔로워/팔로잉 목록·수가 일치한다. 언팔로우 후 목록·수·상태에 취소 결과가 반영된다.

### 6.8 알림 — NTF

**NTF-01 알림 생성·조회·읽음·실시간 갱신**

- [확정] 로그인한 본인의 알림을 최신순으로 조회하며 유형·내용·생성일시·읽음 여부를 표시한다. 없으면 “알림이 없습니다.”를 표시한다.
- [확정] 헤더 알림 아이콘에 본인의 안 읽은 알림 수를 표시한다. 0이면 숫자를 숨기고 로그인 상태에서 새 알림을 수신하면 개수를 실시간 갱신한다.
- [확정] 댓글이 등록되면 게시글 작성자에게 알리되 본인이 작성한 댓글은 자기 알림을 만들지 않는다.
- [확정] 대댓글은 직접 답글을 단 댓글의 작성자에게만 알린다.
- [확정] 팔로우는 팔로우를 받은 사용자에게 알리고 언팔로우 알림은 생성하지 않는다. 자기 팔로우는 COM-03에서 거부한다.
- [확정] 알림을 선택하면 해당 알림을 읽음 처리한다. 모두 읽음은 본인의 안 읽은 알림 전체를 처리하고 아이콘 개수에도 반영한다.
- [확정] 같은 이벤트가 재발생하거나 전달을 재시도해도 수신자별 동일 알림은 한 번만 생성한다.
- [미정] 자기 댓글에 단 대댓글의 알림 여부, 언팔로우 후 다시 팔로우할 때의 이벤트 식별, 중복 방지 키·보관 기준, 실시간 채널·재연결 동기화는 D15에서 정한다. 정의서의 상담 알림은 미정 항목으로 우선 개발 대상에 포함하지 않는다.
- **수용 기준:** 타인 알림 조회·읽음 처리를 거부한다. 댓글·직접 답글·팔로우의 수신 대상과 자기 댓글·언팔로우 제외 규칙을 검증한다. 새 알림·중복 전달·개별 읽음·모두 읽음·재조회 후 목록과 미읽음 수가 일치하고 빈 목록·0개 표시를 구분한다.

### 6.9 공통 미디어 — MED

**MED-01 업로드·연결·조회·교체·제거·정리**

- [확정] 파일 메타데이터는 단일 공통 미디어 테이블로 관리한다. 게시글 사진·동영상, 프로필, 반려동물·건강 기록, 상담 첨부 등은 파일 식별자로 연결한다.
- [확정] 로그인한 사용자가 파일을 업로드하면 완료된 파일의 식별자를 반환한다. 파일별 진행·완료·실패 상태와 실패 사유를 표시한다.
- [확정] 확장자·실제 파일 유형·크기를 검증하고 사용처별 최대 첨부 개수를 제한한다. 지원하지 않는 형식·초과 용량·개수는 거절하고 이유를 안내한다.
- [확정] 게시글·프로필·건강 기록 등 사용처 저장 시 파일의 존재, 업로드 완료 상태와 연결 권한을 검사한다. 미완료·권한 없는 파일을 연결할 수 없다.
- [확정] 사용처의 공개 범위와 현재 조회 권한에 따라 파일을 제공하고, 비공개 파일은 요청마다 접근 권한을 확인한다. 업로드·연결·교체·제거에도 사용자와 사용처 권한을 검사한다.
- [확정] 교체는 새 업로드와 변경사항 저장이 모두 성공한 뒤 기존 연결을 해제한다. 첨부 제거도 변경사항 저장 성공 후 연결을 해제한다. 저장 실패 시 기존 연결을 유지한다.
- [확정] 작성 취소·저장 실패로 남은 미사용 파일과 연결 해제 파일은 정한 보관시간 후 정리한다. 사용 중인 파일은 정리 대상에서 제외한다.
- [확정] 삭제 대상 메타데이터·저장소 파일은 삭제 정책에 따라 처리하고 저장소 삭제 실패를 기록해 재처리한다. 실행 운영체제와 무관하게 업로드·조회할 수 있어야 한다.
- [확정] 삭제되거나 조회할 수 없는 이미지는 대체 이미지를, 동영상·문서는 안내 문구를 표시한다.
- [미정] 허용 형식·용량·사용처별 개수, 파일 연결 구조, 임시·연결 해제 파일 보관시간과 소프트 삭제 원본 보관·파기의 구분은 D19에서 확정한다.
- **수용 기준:** 형식·크기·개수 위반과 권한 없는 연결·변경을 각각 거부한다. 교체·제거 저장 실패 시 기존 첨부가 유지된다. 삭제 콘텐츠의 기존 URL 접근은 차단하고 사용 중인 파일은 정리하지 않는다. 저장소 삭제 재시도로 다른 파일이 삭제되지 않으며 조회 불가 안내가 파일 유형별로 표시된다.

## 7. 상담 상태와 예외 처리

### 7.1 실시간 매칭의 상태

| 단계(제품 흐름, 내부 enum 아님) | 서비스 동작 | 확인할 경계 |
|---|---|---|
| 요청·매칭 대기 | 동물·수단·증상·이미지 접수, 위치 기반 탐색과 진행·대기 시간 표시 | 위치 확인·탐색 세부값·상대 가용 상태(D17) |
| 매칭 완료 | 수의사 한 명 확정, 이름·병원 표시 | 수락 제공 주체·동시성(D04·D17) |
| 미매칭·매칭 전 취소 | 연결하지 않고 결과 안내 | 기한·만료와 늦은 수락 처리(D17) |
| 상담 진행 | 선택한 채팅·화상 연결, 상담 시간·종료 버튼 표시 | 실제 연결·종료 확인·재연결(D06) |
| 상담 종료·내역 | 시간·수의사·상태를 확인하고 제공된 일지 조회, 미작성 안내 | 업무 완료와 일지의 관계(D04·D07) |
| 매칭 후 취소 | 확정된 조건에 따라 상담 취소와 연결 종료 처리 | 주체·허용 시점·연결 종료(D04·D06·D17) |

현재 상태 모델은 보호자 흐름을 설명한다. SQL의 `대기·상담중·완료`만으로 매칭 취소·만료·연결 실패·일지 미작성 구분을 충족한다고 가정하지 않는다. 내부 상태와 이벤트 계약은 D04·D18에서 정한다.

### 7.2 탐색·수락·완료의 경계

CON-05의 기존 반경·시간 합의는 기록으로 보존한다. 최신 시트의 “가장 가까운 병원부터 탐색”에 대한 거리순·단계별 전달 기준과 실제 가용 정보 제공 방식은 D17에서 재확인한다. 보호자는 매칭 진행·취소·결과를 실시간으로 확인하고, 서버는 중복 수락·취소·만료 이벤트를 일관되게 처리한다.

이전 일지 선저장 완료 규칙과 최신 일지 미작성 안내를 함께 추적한다. 보호자의 연결 종료와 업무 완료 사건을 어떻게 분리할지 D04·D07에서 결정한다. 일지가 없다는 이유로 종료 결과·상담 내역 조회를 차단하지 않는다.

### 7.3 개발 전에 사람에게 질문할 항목 [미정]

- 매칭 가용 상태·수락 결과·종료 이벤트를 누가 어떤 인증·인터페이스로 제공하는가?
- 위치 권한 거부·위치 취득 실패, 매칭 기한 경과와 늦은 수락은 어떻게 처리하는가?
- 누가 언제까지 취소할 수 있으며 상담 시작 후 중단·불참·연결 실패는 어떻게 처리하는가?
- 상담 종료·업무 완료·일지 제공을 각각 언제 기록하는가?
- 완료 오처리·분쟁과 탈퇴 계정의 진행 중 상담은 어떻게 처리하는가?

답변 전에는 자동 완료 등 새 동작을 임의 확정하지 않는다.

## 10. 공통 품질 요구사항과 미결정 항목

### 10.1 보안·정보 보호

- 모든 비공개 데이터와 파일에 서버 측 소유권·역할·상담 상태 검사를 적용한다.
- 전송 구간을 보호하고 계정·전화번호·상담 정보의 저장·조회 권한을 제한한다.
- 권한 변경·상담 처리를 감사 가능하게 남긴다. 로그에 건강 기록 본문·실제 전화번호를 그대로 남기지 않는다. 외부 운영 조치의 수신 이력은 연동 계약에 따른다.
- [확정] 계정·반려동물·건강·접종·진료·콘텐츠 삭제는 소프트 삭제로 접근에 반영한다. 기존 데이터·첨부 원본 보관 합의와 최신 미사용 미디어 정리 요구의 적용 대상을 구분한다. 연결 해제만으로 즉시 파일을 파기하지 않으며 실제 정리·보관·파기 기준은 D19에서 확정한다.

### 10.2 신뢰성과 복구

- 상담 이벤트·알림 처리의 중복 실행이 결과를 중복시키지 않아야 한다.
- 외부 연동 실패와 처리 지연을 감지하고 원 요청·이벤트 기준으로 확인·재처리할 수 있어야 한다.
- 백업·복구 절차와 목표 복구 시점·시간을 정하고 실제 복구를 검증한다.
- 처리 실패·일지 미제공·업로드 실패를 식별하고 필요한 실패 통지·재처리 경계를 확인한다.

### 10.3 성능·사용성

- 건강 기록·상담·커뮤니티·알림 목록은 데이터 증가에 대응하는 페이지 조회를 제공한다.
- 목표 동시 사용자·데이터 규모·응답시간 기준과 측정 환경은 개발 완료 전에 확정한다. 수치 미정 상태를 성능 검증 완료로 간주하지 않는다.
- PC·모바일 반응형 웹에서 주요 흐름을 완료할 수 있어야 한다. 지원 화면 크기와 브라우저별 검증 범위는 미정이며 해당 화면 개발 전 질문한다.
- 입력 필드의 이름·오류 안내, 키보드 조작, 명확한 버튼 상태를 제공한다. 상태는 색상만으로 구분하지 않는다.
- 중복 클릭으로 상담 요청·알림이 중복 생성되지 않으며, 통신 실패 후 입력 내용을 가능한 범위에서 보존한다.
- 지원 브라우저·버전은 출시 전 확정한다.

## 11. 데이터 요구사항

첨부 SQL의 물리 테이블과 이 장의 제품 요구를 함께 대조한다. 최신 ERD는 [ERD 문서](erd.md)의 원문 구조·참조 후보·정합성 확인표를 따른다. SQL에 없는 요구는 D18로 남기고 테이블·관계·제약이 구현됐다고 표시하지 않는다.

### 11.1 첨부 SQL과 확인할 차이

- 건강 기록 요구에 대응하는 테이블과 유형별 상세 구조가 첨부 SQL에 없다.
- 반려동물의 종·품종 관계, 체중·기본 예방접종 여부·프로필 연결 등 요구 필드가 원문에 충분히 표현되지 않았다. 예방접종·병원진료도 최신 요구 상세 필드와 차이가 있다.
- 미디어는 공통 테이블 하나로 제공됐으나 사용처 연결·업로드 상태·정리 상태·권한 관계가 없다. 이를 새 컬럼·관계로 임의 확정하지 않는다.
- 실시간 상담의 수의사 필수값과 매칭 전 상대 미정 상태가 충돌할 수 있다. 요청·매칭·취소·만료·일지 미작성, 상대 제공 계약과 저장 구조를 함께 정한다.
- 알림은 이벤트별 수신자 중복 방지를 보장할 키·제약을 확정해야 한다. 계정의 소셜 비밀번호 NULL·이메일 유일성도 원문 제약과 대조한다.

후기 텍스트·일지·프로필 표현과 실제 SQL의 차이는 D07·D16·D18에서 확인한다.

## 13. 개발 착수 절차

1. 개발 요청에 기능 ID, 목적·범위, 적용 공통 정책의 절 번호, 관련 D ID, 수용 기준·Q ID를 적는다. 6.10에서 연결된 기능도 확인한다.
2. 미정 질문이 해당 작업에 영향을 주는지 구분한다. 영향을 받는 동작은 사람에게 질문하고 답변 전 구현·QA 기대값 확정을 보류한다. 질문과 무관한 확정 작업은 진행할 수 있다.
3. 답변과 결정자·결정일·사유를 해당 D 항목 및 15장 변경 이력에 남기고 관련 기능·화면·권한·상태·검증 기준을 함께 갱신한다. 외부 검토가 필요한 항목은 검토 여부도 구분한다.
4. 확정된 범위만 구현·검증한다. 내부 상태·API·DB·기술 선택은 별도 상세 설계에서 사람과 합의하며 이 PRD의 표를 물리 설계나 enum으로 그대로 확정하지 않는다.
5. 결과에는 기능 ID·Q ID별 실행한 검증과 결과, 보류된 D ID, 실제 서버·DB·외부 연동의 미검증 범위를 남긴다. 개발 순서·일정·인력 배정은 별도로 협의한다.
