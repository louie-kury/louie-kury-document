# 미디어 서비스 경계와 저장 흐름

- 상태: 사용자 승인 설계, 미구현 (2026-11-26)
- 범위: 미디어·커뮤니티 등 사용처 도메인과 게이트웨이의 공통 계약. 세부 API 및 데이터 구조는 구현 전 확정한다.

## 결정

실제 파일은 AWS S3에 저장하고 미디어 서비스가 파일을 받아 업로드·기본 검사·정보와 사용처 연결을 관리한다. 파일 하나와 현재 연결은 Media 어그리게이트이며 미디어와 첨부 테이블은 분리한다. 한 파일의 동시 사용처는 한 곳이고 업로더 본인만 연결할 수 있다. 게시글의 첨부 순서를 유지한다.

게이트웨이는 인증된 사용자 key를 신뢰할 수 있게 전달한다. 미디어 파일 요청마다 미디어 서비스는 내부 HTTP로 사용처 서비스에 비회원 또는 사용자 key와 대상 ID를 전달해 현재 공개·삭제·숨김 상태와 조회 권한을 확인한 뒤, 허용된 파일을 S3에서 가져와 전달한다. 공개 게시글은 비회원도 조회할 수 있다. 확인 실패 시 파일을 제공하지 않는다. 이미 전달된 파일은 회수할 수 없다.

게시글은 저장 버튼 후 파일 업로드, 비공개 임시 글 저장, 파일 연결을 거쳐 공개한다. 연결 실패 시 임시 글과 파일을 보관하고 사용자 재시도를 안내한다. 마지막 작성·재시도 24시간 후 도메인이 정리를 시작하고 미디어 서비스는 사용·진행 여부를 확인한다. 각 도메인은 사용자 key와 작업 ID로 전체 작업을 관리한다. 결과가 불명확하면 파일을 보호하고 사용자가 같은 ID로 재시도할 때 확인한다.

연결 해제된 파일은 24시간 후 정리하며 S3 원본은 삭제하고 미디어 기록은 소프트 삭제한다. 삭제는 최초 시도 후 10초·30초·60초 간격으로 최대 3회 재시도하며 최종 실패는 운영자가 확인한다. 소프트 삭제된 부모에 연결된 원본은 보관하고 접근을 차단한다.

## 영향과 미정

사전 서명 S3 주소로 직접 제공하면 만료 전 기존 주소가 재사용될 수 있으므로 요청마다 현재 권한을 확인하는 방식으로 변경한다. 이 방식은 미디어 서비스의 파일 전달 및 도메인 권한 확인 부하가 있다. 기존 ERD SQL의 단일 연결 제약과 순서 컬럼은 아직 반영되지 않았다.

서비스 간 신뢰·인증, 정확한 API와 오류, 다중 파일의 재시도 식별, 보관 작업의 경합 방지 및 상태 저장 방식은 구현 전 설계한다. 새 레포를 만들고 기존 S3 어댑터·기본 파일 검사 등 적합한 코드와 테스트를 선별해 재사용한다. 이 문서는 구현·운영 검증 결과가 아니다.
